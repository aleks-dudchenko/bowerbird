# Zbirka — локальна бібліотека дизайн-референсів

> Робоча назва — плейсхолдер. Альтернативи: `Refka`, `Moodbin`, `Zbirka`.
> Перейменувати треба **до** першого коміту, поки не з'явилися посилання.

Open source (MIT) десктоп-застосунок: мікс того, що добре зроблено в DIIVO
(офлайн-AI, широкий набір форматів, разова ціна, без акаунта) і в GatherOS
(нескінченний канвас замість сітки, авто-теги, rediscover).

---

## 1. Правова рамка — прочитати перш ніж писати код

Репозиторій GatherOS публічний, але **без ліцензії** (`license: null`).
Публічний ≠ вільний: діє звичайне авторське право, усі права застережені.

Правила, яких тримаємось:

| Можна | Не можна |
|---|---|
| Повторювати **ідеї** та набір фіч (ідеї не охороняються) | Копіювати код, навіть шматками |
| Дивитись на UX і робити свій | Копіювати CSS, іконки, тексти, скриншоти |
| Згадати в README, що надихнули DIIVO і GatherOS | Використовувати назви `GatherOS` / `DIIVO` у бренді |
| Читати їхній README для розуміння сценаріїв | Тримати їхній репозиторій відкритим під час написання свого коду |

**Clean room на практиці:** спочатку фіксуємо список фіч своїми словами (цей
файл), далі пишемо реалізацію з нуля, не звіряючись із чужим кодом. Якщо
захотілось підглянути «а як вони зробили X» — краще подивитись у документацію
Electron / SQLite, а не в їхній `src/`.

## 3. Ключове архітектурне рішення: папка — джерело правди

І DIIVO, і GatherOS тримають стан у SQLite. DIIVO ще й пропонує синк через
Dropbox/iCloud — а SQLite у синхронізованій папці рано чи пізно псується
при паралельному доступі з двох машин.

Робимо інакше:

```
MyLibrary/                     ← ця папка може лежати в Dropbox/iCloud
├─ items/
│  ├─ 2026/08/a7f3k2.png
│  └─ 2026/08/a7f3k2.json      ← сайдкар: теги, нотатки, джерело, дата
└─ .zbirka/
   ├─ index.db                 ← SQLite: кеш, FTS, ембединги
   └─ thumbs/
```

- `items/` синхронізується як звичайні файли — конфліктів немає.
- `.zbirka/` **локальна на кожній машині** і повністю відновлювана: видалив —
  застосунок перебудував індекс із сайдкарів.
- Бонус: бібліотека читається без застосунку, портується, лягає в git.

Це не тільки надійніше — це чесна відповідь на «а що як застосунок помре».

## 4. Стек

| Шар | Вибір | Чому саме так |
|---|---|---|
| Оболонка | **Electron** + electron-builder | Rust/cargo на машині немає, Tauri = зайвий бар'єр. Electron має купу прикладів → AI-асистент пише його впевненіше |
| UI | **React + Vite** | стандарт, швидкий HMR |
| БД | **better-sqlite3** | синхронний, швидкий, FTS5 з коробки |
| Зображення | **sharp** | тумбнейли, HEIC, ресайз |
| PDF | **pdfjs-dist** | перша сторінка → превʼю |
| Відео | **ffmpeg** (вже стоїть у brew) | постер-кадр |
| Кольори | **node-vibrant** | палітра → пошук за кольором |
| AI | **@huggingface/transformers** (ONNX Runtime) | CLIP локально, без мережі після першого завантаження |
| OCR | **macOS Vision** через свій Swift-хелпер | Xcode + Swift 6.3 вже є; якість вища за tesseract, включно з українською |
| Канвас | звичайний DOM + CSS `transform` | для MVP простіше за konva; якщо просяде перф на 1000+ айтемів — переїзд на react-konva |

Все під MIT/Apache — конфліктів із власною MIT-ліцензією немає.

## 5. Схема даних (стартова)

```sql
items(id, path, sha256, kind, w, h, bytes, created_at, added_at,
      source_url, title, note, colors_json)
tags(id, name)
item_tags(item_id, tag_id)
collections(id, name, parent_id)
item_collections(item_id, collection_id, sort)
spaces(id, name)                       -- канвас
space_items(space_id, item_id, x, y, w, h, z, rotation)
embeddings(item_id, vec BLOB)          -- Float32Array(512) від CLIP
ocr(item_id, text)
items_fts                              -- FTS5: title, note, ocr, tags, source_url
```

Пошук по вектору на старті — перебором у JS: 20k айтемів × 512 float = 40 МБ
в памʼяті, косинус по всьому масиву ≈ 10 мс. `sqlite-vec` підключаємо тільки
якщо бібліотека переросте ~100k.

## 6. Локальний AI — конкретика

**Семантичний пошук.** Модель `Xenova/clip-vit-base-patch32` через
transformers.js. Одна модель дає і ембединг картинки, і ембединг тексту в
той самий простір — тому запит «синій градієнт з великою типографікою»
знаходить картинку без жодного тега.

- вага ~150 МБ, качається один раз, далі повний офлайн;
- на M-серії ~50–100 мс на картинку при індексації;
- індексація фонова, черга з прогресом, застосунок не блокується.

**OCR.** Swift-бінарник на ~40 рядків з `VNRecognizeTextRequest`, збирається
в `build/` і кладеться в ресурси застосунку. Перевірити підтримку `uk` на
macOS 26 через `VNRecognizeTextRequest.supportedRecognitionLanguages`.
Фолбек для не-Mac — tesseract.js, але явно позначити його як гірший.

**Авто-теги.** Без хмари це zero-shot класифікація CLIP по власному словнику
(~300 дизайнерських термінів: `brutalist`, `serif`, `dark ui`, `packaging`…).
Гірше за GPT-4o, але безкоштовно й офлайн. У README написати чесно.

## 7. Мілстоуни

Критерій готовності = те, що можна показати, а не «код написано».

**M0 — Скелет (0.5 дня)**
Electron+Vite+React запускається, порожнє вікно, `npm run dev` працює.
Репо ініціалізовано, MIT LICENSE на місці, перший коміт.

**M1 — Бібліотека (2–3 вечори)**
Вибір папки бібліотеки. Drag-n-drop файлів. Копіювання в `items/` + сайдкар.
Тумбнейли (sharp). Masonry-сітка. Детальна панель. Видалення.
*Готово, коли: кинув 200 картинок — вони збереглися, відкрилися після
перезапуску, а видалення `.zbirka/` не втратило нічого.*

**M2 — Пошук (2–3 вечори)**
FTS5 по назві/нотатках/тегах. Теги, колекції. Пошук за кольором.
Клавіатура: `j/k` навігація, `t` теги, `b` колекція, `f` обране, `/` пошук.
*Готово, коли: знаходжу картинку за тегом і за кольором швидше, ніж у Finder.*

**M3 — Канвас (3–4 вечори) ← головна фіча**
Spaces: нескінченне полотно, пан/зум, перетягування айтемів, мультивибір,
снап-лінії, збереження позицій у `space_items`.
*Готово, коли: зібрав мудборд на 30 картинок і він відкрився таким самим.*

**M4 — AI + формати (3–4 вечори)**
CLIP-індексація з прогресом, семантичний пошук. OCR-хелпер. Zero-shot теги.
PDF/відео-превʼю, рендер SVG і Lottie. Rediscover.
*Готово, коли: запит «мінімалістична упаковка» знаходить релевантне без тегів.*

**M5 — Chrome-екстеншн (1–2 вечори)**
MV3, контекстне меню «Save to Zbirka», локальний HTTP на `127.0.0.1`
з токеном, сервер живий лише поки застосунок відкритий.

**M6 — Реліз і open source обвʼязка (1–2 вечори)**
Див. розділ 8.

Реалістично: **MVP (M0–M2) — тиждень вечорів. Повний мікс — 4–6 тижнів**
у темпі побічного проєкту. Мій попередній «кілька вечорів» стосувався саме
MVP, не всього списку.

## 8. Open source обвʼязка

- `README.md` — що це, скриншот/гіфка, встановлення, обмеження, «надихнули

- **Підпис і нотаризація**: без Apple Developer ($99/рік) застосунок
  запускатиметься тільки через `xattr -dr com.apple.quarantine`. Для
  безкоштовного проєкту це нормально — просто написати інструкцію в README.
- Жодної телеметрії. Написати це в README окремим рядком — це аргумент.

## 9. Ризики і чесні застереження

| Ризик | Що робити |
|---|---|
| HEIC у prebuilt sharp може не мати libheif | перевірити на M1 і не обіцяти HEIC, поки не підтверджено |
| Модель CLIP ~150 МБ на першому запуску | якщо не хочеться — качати за запитом, при першій AI-дії |
| Vision може не мати `uk` | перевірити на старті M4, у README вказати реальний список мов |
| Electron важкий (~120 МБ .dmg) | прийняти, це ціна швидкості розробки |
| Проєкт заглохне після M2 | нормально, MVP уже корисний; релізити з M2, не чекати повного міксу |
| Стане другим активним проєктом | за `Активне.md` активний один проєкт — зараз це кар'єрні метрики з дедлайном пітчу. Цей — у «Заморожено», розморозити після закриття поточного |
